BRG(1)borgchart manualBRG(1)



NAME


brg - run teams of coding agents from plain files



SYNOPSIS


brg <COMMAND> [OPTIONS]



DESCRIPTION


Describe each role's model and standing task in a template folder, then brg create <template> <folder> starts a team from it, working in that folder. brg status shows who is alive, what they are doing and their unacked message counts; brg attach drops you into a member's live session; brg stop stops it all, and brg start brings it back.


Members are claude and codex sessions on a private tmux server. They talk over a message bus of durable plain messages and acknowledgements, and a team can be a member of another team.


Early, and expected to change.



BEFORE YOU START


brg runs real agents as you. Before your first brg create:


Codex members without restricted access have full host access and no tool approvals (--sandbox danger-full-access --ask-for-approval never): their commands can read and change anything your user can. That includes every Codex helper in the example team.


Members act as you. They use your logged-in vendor accounts, your git and GitHub credentials, and the MCP connectors set up in each CLI.


Every member draws on your vendor usage: your Claude or Codex plan's allowance, or API spend. brg sets no spending cap.


brg destroy deletes a team's notes and messages, without asking. brg stop keeps them.


Start in a disposable folder, as below, not in a checkout you care about.



QUICK START


This runs the example team, templates/engineering: a Claude lead that starts Codex helpers when its work needs them. You need Rust 1.89 or newer, tmux 3.2 or newer, git with your name and email set (git config --global user.name and user.email: members commit as you), and the claude and codex CLIs, each logged in to a plan that offers the models the role files pin: the models: lines at the top of each templates/engineering/*.md (the lead runs Claude fable, helpers run Codex gpt-6-astra and others). Before each launch the lead asks the seating plugin, brg-seat, whether that plan has room, and waits when it can't tell.


Install brg and the seating plugin from a clone, which also holds the templates:


$ git clone https://github.com/mrshll/borgchart ~/borgchart
$ cd ~/borgchart
$ cargo install --locked --path .
$ cargo install --locked --path plugins/seat


Point brg at the clone's templates, and check them:


$ mkdir -p ~/.config/borgchart
$ printf 'schema: 1\nauto_trust: true\ntemplates: [~/borgchart/templates]\n' > ~/.config/borgchart/config.yaml
$ brg validate engineering


validate ends its first line with ok: 4 role(s), 1 plugin(s). auto_trust: true has brg trust each member's folder, so a new helper doesn't stop at its CLI's folder-trust screen.


Make a disposable git repository, and start a team in it:


$ mkdir ~/brg-first-team
$ cd ~/brg-first-team
$ git init
$ git commit --allow-empty -m "Start"
$ brg create engineering


create prints the team's tree. The team's ID is engineering- and four letters or digits, its lead's lead- and four more: engineering-k3f9 and lead-q8m3 below stand for yours. Run brg status until the lead shows idle. If it shows blocked, at its folder-trust screen or another prompt, open its session with brg attach engineering-k3f9/lead-q8m3, answer the prompt yourself, and detach with Ctrl-b, then d.


Send the lead a small task:


$ brg msg send engineering-k3f9/lead-q8m3 "Write HELLO.md in this folder with one line saying hello, then reply to me by message. Do it yourself; start no helpers."


send returns at once; the lead works in its own session, and brg status shows it working meanwhile. Its reply is a message to you, external:owner. Run brg msg list --team engineering-k3f9 --full until the reply appears, then see the result, and acknowledge the reply by its ID (m2 here):


$ brg msg list --team engineering-k3f9 --full
$ cat HELLO.md
$ brg msg ack --team engineering-k3f9 m2


brg attach shows the lead's session at any time, and you can talk to the lead there too.


Stop the team when you're done:


$ brg stop engineering-k3f9


brg start engineering-k3f9 brings it back, with its notes and messages. brg destroy engineering-k3f9 stops it and deletes them.



COMMANDS



Team templates




templates
List available team templates and their teams


validate
Check a team template and brg's configuration; starts nothing


secrets
List the secrets a template's plugins need, and whether each is set




Teams and members




create
Make a team from a team template, or a member of a role


start
Bring a team to what should be running, or start one member


stop
Stop a team and all its child teams deepest first, or one member


delete
Remove a stopped team, or a stopped member


status
Show a team tree, or every top-level one, with nested child teams


attach
Open a member's live session (detach with your tmux prefix, then d)


logs
Show a member's or plugin's recent output




Messages




msg
Send, list, read, acknowledge, wait for and check messages




Cleanup




cleanup
Remove what brg left behind for deleted members and child teams


destroy
Stop a whole tree and delete its records, notes and messages




brg help <command> or brg <command> --help gives a command's details.
